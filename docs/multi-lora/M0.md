GPU memory breakdown (identical across vanilla / LoRA, ngl=99):
`2529 MiB = 1825 (model) + 448 (context) + 256 (compute)`. Host process RSS
328 MiB. The LoRA tensors (~47 MB on disk, ~94 MB f16 in memory) do not show as
a separate row in the breakdown printer — they are folded into the model
allocator's accounting; this is a llama.cpp reporting limitation, not a real
zero-cost.

### Caveats

- LoRA decode is ~19 % slower than vanilla on Adreno (12.61 → 10.24 tok/s),
  notably worse than the host CPU's 13 %. Likely the r=16 LoRA matmul
  (`x@A → seq×16` then `…@B → seq×hidden`) under-utilises Adreno's wide ALUs.
  Spec §6.2 already calls this out as accepted for first version; M5+ stretch
  goal is a custom OpenCL multi-LoRA kernel.
- The LoRA prompt-eval timing prints as `0.01 ms / 53 tokens` — appears to be
  a llama.cpp display rounding bug for runs that hit the LoRA path (host CPU
  showed the same anomaly). Real prefill is reconstructable as
  `total_time − eval_time − sample_time` ≈ 1100 ms. Worth filing upstream but
  not blocking.
- The OpenCL kernel cache lives in app-private storage and survives between
  runs; first launch from a fresh boot will pay the ~22 s recompile cost
  again. M1 bench harness should warm up before recording metrics.

## Implementation Notes (spec deviations)

See `docs/multi-lora/IMPLEMENTATION_GUIDE.md` §4.M0 — same notes appended there.

1. **`-DLLAMA_BUILD_SERVER=OFF` breaks `llama-cli`** (spec §2.3 build template).
   `tools/cli/CMakeLists.txt` links `server-context`. Build either with
   `LLAMA_BUILD_SERVER` left at default, or refactor when M1 starts.

2. **`llama-cli` is now interactive-only.** Passing `-no-cnv` returns
   `--no-conversation is not supported by llama-cli; please use llama-completion
   instead`. The spec's M0 acceptance sentence says
   `llama-cli --model … --lora … -p "hello"` — that command would *enter
   conversation mode*, so the right binary for M0 prompt-and-go is
   `llama-completion`. Updating spec wording is a one-line fix; do at M1
   alongside the API-symbol grep (per `known-issues.md` I-3).

3. **Base-model HF id is gated.** `meta-llama/Llama-3.2-3B-Instruct` returns 401
   without auth; `convert_lora_to_gguf.py` falls back to
   `unsloth/Llama-3.2-3B-Instruct` mirror. Recorded above for reproducibility.

4. **Default `--ctx-size 0` loads the model's full window** (131K for Llama-3.2)
   and balloons host RSS to 18 GB. M1+ should pin a small ctx (4096 default,
   raise via flag) — important for Android where 12–16 GB RAM is the cap.
