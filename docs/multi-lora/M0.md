identical prompt (e.g. on the train word-problem, vanilla opens
"Let's break it down step by step", LoRA opens "Here's the step-by-step solution"
and re-orders the reasoning steps). Outputs in `results/M0a/{vanilla,lora,style_*}.out`.

## Implementation Notes (spec deviations)

See `docs/multi-lora/IMPLEMENTATION_GUIDE.md` §4.M0 — same notes appended there.

1. **`-DLLAMA_BUILD_SERVER=OFF` breaks `llama-cli`** (spec §2.3 build template).
   `tools/cli/CMakeLists.txt` links `server-context`. Build either with
   `LLAMA_BUILD_SERVER` left at default, or refactor when M1 starts.

2. **`llama-cli` is now interactive-only.** Passing `-no-cnv` returns
   `--no-conversation is not supported by llama-cli; please use llama-completion
   instead`. The spec's M0 acceptance sentence says
   `llama-cli --model … --lora … -p "hello"` — that command would *enter
   conversation mode*, so the right binary for M0 prompt-and-go is
   `llama-completion`. Updating spec wording is a one-line fix; do at M1
   alongside the API-symbol grep (per `known-issues.md` I-3).

3. **Base-model HF id is gated.** `meta-llama/Llama-3.2-3B-Instruct` returns 401
   without auth; `convert_lora_to_gguf.py` falls back to
   `unsloth/Llama-3.2-3B-Instruct` mirror. Recorded above for reproducibility.

4. **Default `--ctx-size 0` loads the model's full window** (131K for Llama-3.2)
   and balloons host RSS to 18 GB. M1+ should pin a small ctx (4096 default,
   raise via flag) — important for Android where 12–16 GB RAM is the cap.
