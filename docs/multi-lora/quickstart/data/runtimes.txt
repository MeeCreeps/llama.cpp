Demo runtimes — OnePlus 12 (Snapdragon 8 Gen 3, Adreno 750, OpenCL 3.0)

Trace: 5 requests, 3 LoRA adapters (reasoning, hebrew, summary),
       max_output=24, arrival_time=0 for all.

  vanilla per-process (5 × llama-completion --lora ...):
      105.0 s   (≈ 21.0 s / req)

  ours (multi-lora-bench --n-slots=4 --max-adapter-mem-mb 0):
       34.0 s   (≈  6.8 s / req)

  speedup: 3.09×

Where the savings come from:
  - vanilla pays model load (~1.7 GB GGUF mmap) + OpenCL backend init
    + kernel cache reload PER request → ~3–4 s × 5 = ~15–20 s overhead
  - ours pays it once at startup
  - ours batches the two reasoning requests that arrive together
    (req_00000 + req_00003) into a single decode step
  - ours hits its adapter cache on req_00004 (reasoning already
    resident) → acquire_ms = 0 vs ~80 ms cold load
